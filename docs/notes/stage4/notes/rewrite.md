## Context

[derivation_game.md](derivation_game.md) is the project's **tutorial-first background reference** for the synthesis derivation game — 16 sections, figures D1–D6 (regenerated from the live grammar by `scripts/plotting/plot_derivation_game_diagrams.py`), §§1–13 needing only basic sets/functions/FSMs/CFGs, §§14–15 the dense formal / code-audit layer. It currently documents the **aux-var grammar**:

- §1 (mental model) — the 4-objects table lists `q` = `PartialRule(schema, action_args, aux_vars, state_lits, goal_lits)` and `h` ∈ {`policy`, `action_schema`, `aux_var`, `pre_lit`, `goal_lit`, `None`}.
- §3 (arrow labels) — the vocabulary includes `SKIP_AUX` ("do *not* add an extra variable") and `add_aux:ball` / `add_aux:room` ("introduce one **witness variable** `?aux_0`"); the content-vs-cursor split lists `add_aux:T` as content and `SKIP_AUX` as cursor.
- §4 (hole-state machine) — the FSM diagram has an `aux_var` node between `action_schema` and `pre_lit`; the production catalogue table has two `aux_var` rows (`SKIP_AUX`, `add_aux:{type}`); the naming-conventions note mentions "the **auxiliary** `?aux_{j}` (Stage 2 caps `V_aux = 1`)"; "the `goal_lit` hole is the widest … `M = compute_max_productions = 13`"; the `goal_lit` row mentions the `require_goal_var_connected` filter.
- §5 (worked derivation) — a **9-step** play building `ρ₁` (drop-at-goal), with step 3 = `SKIP_AUX`; "Each rule costs **5** fixed productions — `ADD_RULE`, `schema=…`, the aux decision (`SKIP_AUX` or `add_aux:T`), `STOP_PRE`, `FINISH_RULE`"; `ℓ(π) = 1 + Σ(5 + |pre_i| + |goal_i|)`, range `[6, R(L_S+L_G+5)+1]`; figures D3, D5, D6 captioned to match.
- §6 (partial-rule fields) — the boxed `q = (schema, action_args, aux_vars, state_lits, goal_lits)` and the field table row `aux_vars` = "extra **witness** variables used only in conditions, never in the action"; figure D4 (state anatomy).
- §8 ("Auxiliary variables as witnesses") — a whole section on `?aux_0`.
- §11 (failure modes) — the disconnected-`?aux_0` pathology (cross-linked to `legacy/02.md` §H4) is presented as something the `require_goal_var_connected` *filter* removes.
- §13 (grammar as a typed attributed CFG) — has an `Aux → SKIP | add_aux:τ` nonterminal.
- §14 (the derivation game as an MDP) — `M = compute_max_productions = 13` action-head size; the hole set includes `aux_var`; the derivation-length bound uses the 5-fixed-productions-per-rule figure.
- §15 (code-fidelity audit) — line refs into `lifted_grammar.py` / `lifted_derivation.py` / `lifted_encoding.py` including the `aux_var` hole, `add_aux` productions, `PartialRule.aux_vars`, and the `_KIND_AUX_VAR` encoding node.
- §16 (figure index / notation bridge / cross-links) — the notation-bridge table includes `aux_vars` ↔ "witness variables".

Stage 2 ([../02_plan.md](../02_plan.md), [../02.md](../02.md)) replaced all of that with **occurrence-introduced variables**: no `aux_var` hole; the holes are `policy → action_schema → pre_lit → goal_lit → (FINISH_RULE → policy) → STOP_POLICY → ⊥`; action variables enter scope when the schema is chosen (`?r_0, ?b_1, …`); a state (precondition) literal *may* introduce a fresh typed **body-local variable** `?v_0, ?v_1, …` in any argument position that uses it (capped by `LiftedGrammarConfig.max_body_local_vars`, default 2); a goal literal introduces *no* variables (its arguments must already be action arguments or body-local variables of a positive state literal) — so goal-literal-variable connectedness is *structural*, not a filter, and `require_goal_var_connected` is vacuous-by-construction. `LiftedGrammarConfig.max_aux_vars` is gone; `lifted_encoding._KIND_AUX_VAR` is gone; `PartialRule.aux_vars` is now `PartialRule.body_local_vars`; `compute_max_productions` has a new (larger) value (no longer 13). So `derivation_game.md` is now **wrong about the live code** and must be rewritten.

This is a **docs-only follow-up to Stage 2**, executed *after* Stage 2 lands (so the note is audited against landed code, not a proposal). It also updates the figure-generating script and regenerates the figures. There is no separate post-rewrite results companion — the "result" is the rewritten note itself, plus the regenerated figures.
