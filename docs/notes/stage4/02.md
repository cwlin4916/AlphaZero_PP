## §0 Dataset and vocabulary

The objects this companion talks about, in plain prose, before any notation:

- **Environment.** `GripperLiteEnv(B)` ([instances/gripper_lite/env.py](../../../src/alphazeropp/instances/gripper_lite/env.py)) — the relational Gripper-lite env from Stage 1: two rooms, $B$ balls, a one-gripper robot, goal = every ball in `room_b`. Each cell of the grid below freezes one `GripperLiteEnv(B)` and uses it for train, in-eval and out-eval (no held-out instance).
- **Policy / terminal.** A *policy* (a.k.a. a *program* $\pi$) is a typed lifted decision list — an ordered list of rules $\rho_1,\dots,\rho_R$, each $\rho_i$ a body $\Rightarrow$ action schema. A *terminal* is a complete derivation in the grammar of §4: starting from the empty policy and applying productions until `STOP_POLICY`, the result is one policy. Terminals are pretty-printed and de-duplicated by `policy_pretty`; *unique terminals* are the de-duplicated set.
- **Episode / play.** One *episode* (a.k.a. a *play*) is one self-play game of `LiftedDerivationGame` ([lifted_derivation.py:169-287](../../../src/alphazeropp/synthesis/lifted_derivation.py#L169-L287)) driven by MCTS under a uniform prior `UniformPolicyValueNet` ([derivation_game.py:293](../../../src/alphazeropp/synthesis/derivation_game.py#L293)); it ends at one terminal policy, which is then scored by `LiftedLeafEvaluator` ([lifted_leaf_evaluator.py](../../../src/alphazeropp/synthesis/lifted_leaf_evaluator.py)) over the cell's frozen env.
- **Cell.** A *cell* is one $(B, \texttt{mcts\_sims}, \texttt{seed})$ triple. Each cell runs $n_{\text{ep}}$ episodes (the schedule shrinks $n_{\text{ep}}$ as `mcts_sims` grows — §11), logs every terminal, and writes one `{cell}_summary.json` + `{cell}_best.jsonl` under [data/minimal_mcts/](data/minimal_mcts/).
- **Classification.** Each terminal policy is labelled `solver` / `reasonable` / `degenerate` by a fixed rule applied to a fresh rollout ([run_lifted_gripper_mcts_minimal.py:78-123](../../../scripts/run/run_lifted_gripper_mcts_minimal.py#L78-L123)) — formalised in §3.
- **Strict grammar config.** `strict_grammar_config()` ([lifted_grammar.py](../../../src/alphazeropp/synthesis/lifted_grammar.py)) — the redesigned grammar's default: `max_pre_literals=3`, `max_goal_literals=1`, `max_body_local_vars=2`, `allow_state_negation=False`, `allow_disjunction=False`, `allow_constants=False`, `goal_predicate_relevance=True`. `max_rules` is set per run (3 for $B{=}1$, 4 for $B{=}2$).

## §1 Introduction

This companion reports an experimental stage with two parts — a grammar redesign, then a minimal search run over it. Treated as an experimental writeup:

1. **Research question.** *Can uniform-prior MCTS over the redesigned lifted derivation grammar find reasonable Gripper-lite policies for $B=1$ and $B=2$ (same-$B$ train and eval)?* This is the feasibility gate before any learned prior is built: if a flat prior cannot reach a single solver in the search space, a learned one has nothing to amplify.
2. **The grammar cutover.** The old grammar's standalone *auxiliary-variable* phase (the `aux_var` hole, the `add_aux` / `SKIP_AUX` productions, `max_aux_vars`, `?aux_i` names — full inventory in §4 and [Appendix B](#appendix-b-module-api-and-code-notes)) is removed (the redesign proposed in [01_draft_lifted_policy_az.md](01_draft_lifted_policy_az.md) §8). Variables now enter a rule's scope **only at the literal occurrence that first uses them**: action variables when the action schema is chosen (named by schema position, `?b_0`, `?r_1`, …), fresh typed *body-local* variables (`?v_0`, `?v_1`, …) when a precondition literal first mentions them, and **no new variables in goal literals**.
3. **Structural consequence (Math).** Because a goal literal can introduce no variable, every goal-literal variable of a grammar-produced rule is justified by an action argument or a positive state literal. So the "disconnected `?aux_0` in a goal literal" pathology of [legacy/02.md](legacy/02.md) §H4 is *impossible to express*, not merely filtered out (§4, boxed invariant; §5, audit row).
4. **The run.** A uniform-`UniformPolicyValueNet`-prior MCTS run on `LiftedDerivationGame` → `LiftedLeafEvaluator` over a frozen `GripperLiteEnv(B)`, for $B\in\{1,2\}$, on a $\texttt{mcts\_sims}\times\texttt{seed}$ grid; every terminal classified `solver` / `reasonable` / `degenerate` and logged.
5. **$B=1$ answer (Emp/Comp).** Yes — genuine 3-rule pick→move→drop solvers, scoring equal to the hand policy, found in 7 of 15 grid cells (§7); the solvers are verified by rollout (§9), not score-formula artifacts.
6. **$B=2$ answer (Emp/Comp).** Yes, but rarely — a solver in 2 of 10 grid cells; at this budget the modal terminal under a uniform prior is degenerate (§8, §10).
7. **Out of scope.** No learned policy/value net, no held-out generalization ($B=3$, $J_{\text{out}}$), no Doors MCTS, no Stage-2.5 landscape enumeration, no score-variant plots, no PG3 comparison (§2, §13, §14).

## §2 Scope

**In scope.** The grammar cutover; a uniform-`UniformPolicyValueNet`-prior MCTS run on `LiftedDerivationGame` → `LiftedLeafEvaluator` over a frozen `GripperLiteEnv(B)`; a per-policy classification (solver / reasonable / degenerate) and the JSONL/CSV logs that back it.

## §3 Notation and setup

Symbols used in more than one section. Block-local symbols are introduced at their formula.

| symbol | meaning |
|---|---|
| $B$ | number of balls; here $B\in\{1,2\}$ |
| $\pi=(\rho_1,\dots,\rho_R)$ | a policy (decision list); $\rho_i$ = one rule (body $\Rightarrow$ action schema) |
| $\sigma_A$ | the action signature — each schema's argument types (Gripper-lite: `move:(room,room)`, `pick:(ball,room)`, `drop:(ball,room)`) |
| `?b_i` / `?r_i` | action variables, named by schema position (`?{type-prefix}_{i}`) |
| `?v_i` | body-local variables, named by first-occurrence order within and across precondition literals |
| `max_rules`, `max_pre_literals`, `max_body_local_vars` | grammar caps (`strict_grammar_config`); here `max_pre_literals=3`, `max_body_local_vars=2`, `max_rules`$\in\{3,4\}$ |
| $M=\mathrm{computeMaxProductions}(\mathrm{cfg},\sigma_A)$ | fixed width of the derivation-game action head; $M=26$ for the strict Gripper-lite config (§4) |
| `mcts_sims` | MCTS simulations per move; $\in\{128,512,2048\}$ for $B{=}1$, $\{512,2048\}$ for $B{=}2$ (committed grid) |
| $n_{\text{ep}}$ | episodes per cell; schedule $\{128{:}64,\;512{:}32,\;2048{:}16,\;8192{:}8\}$ (§11) |
| $\mathrm{solveRate},\ \mathrm{avgProgress},\ \mathrm{avgSteps},\ \mathrm{numNoops}$ | aggregate rollout metrics of a policy over its env(s) ([lifted_leaf_evaluator.py:106-111](../../../src/alphazeropp/synthesis/lifted_leaf_evaluator.py#L106-L111)) |
| cell | one $(B,\texttt{mcts\_sims},\texttt{seed})$ triple |

The leaf evaluator turns a policy's aggregate rollout metrics into a scalar score. The score is

$$
\boxed{\;\mathrm{score}(\pi)\;=\;\mathrm{solveRate}(\pi)\;+\;\tfrac14\,\mathrm{avgProgress}(\pi)\;-\;\tfrac1{100}\,\mathrm{avgSteps}(\pi)\;-\;\tfrac1{20}\,\mathrm{numNoops}(\pi)\;}
$$

— implemented at [lifted_leaf_evaluator.py:114-120](../../../src/alphazeropp/synthesis/lifted_leaf_evaluator.py#L114-L120). A hand-quality $B{=}1$ solver (solves in $\mathrm{steps}(1)=3$ steps, $0$ noops, $\mathrm{avgProgress}=1$) scores $1+0.25-0.03=1.22$; a $B{=}2$ hand-quality solver ($\mathrm{steps}(2)=7$) scores $1+0.25-0.07=1.18$; a 1-rule always-noop policy floors at $-0.05$. ($\mathrm{steps}(B)=4B-1$ is the Stage-1 hand-policy plan length, [01.md](01.md) §3.)

The classifier labels a terminal by what a fresh rollout from the initial state does. The classification of a policy $\pi$ is

$$
\mathrm{class}(\pi)=\begin{cases}
\mathrm{solver} & \text{the rollout reaches }\texttt{env.is\_solved()}\\
\mathrm{reasonable} & \mathrm{progress}(\pi)>0\ \wedge\ \{\texttt{pick},\texttt{move},\texttt{drop}\}\subseteq\mathrm{schemasFired}(\pi)\\
\mathrm{degenerate} & \text{otherwise (first }\texttt{interpret}\text{ returns }\texttt{None}\text{, or zero progress)}
\end{cases}
$$

— implemented at [run_lifted_gripper_mcts_minimal.py:78-123](../../../scripts/run/run_lifted_gripper_mcts_minimal.py#L78-L123). Prior: `UniformPolicyValueNet` (flat policy head, zero value). MCTS exploration constant `c_exploration = 1.5`.

## §4 The grammar redesign

> **Goal.** Establish what the redesigned grammar can and cannot express, the shape of its derivation game, and the structural invariant that the cutover buys for free.

### Hole-state machine — before / after

```
  OLD (aux-var grammar)                         NEW (occurrence-introduced vars)

  policy ──ADD_RULE──▶ action_schema             policy ──ADD_RULE──▶ action_schema
                          │ schema=…                                    │ schema=…
                          ▼                                             ▼
                       aux_var ◀─┐ add_aux:T                          pre_lit ◀─┐ pre:ℓ  (ℓ may carry a
                          │      └──────┘                                │      └────┘    fresh ?v_i)
                  SKIP_AUX│                                       STOP_PRE│
                          ▼                                                   ▼
                       pre_lit ◀─┐ pre:ℓ                                   goal_lit ◀─┐ goal:ℓ  (ℓ uses
                          │ STOP_PRE └────┘                                   │       └─────┘   in-scope vars only)
                          ▼                                                   │ FINISH_RULE
                       goal_lit ◀─┐ goal:ℓ                                    ▼
                          │ FINISH_RULE          ┌──────────────── policy ──STOP_POLICY──▶ ⊥
                          ▼                       └── (back to ADD_RULE for the next rule)
        policy ──STOP_POLICY──▶ ⊥
```

Holes: `{policy, action_schema, pre_lit, goal_lit, ⊥}` — the `aux_var` hole is removed (`_HOLE_ID` renumbered, `_KIND_AUX_VAR` deleted; symbol-rename details in [Appendix B](#appendix-b-module-api-and-code-notes)). The `require_goal_var_connected` flag is kept for config-shape stability but is now **vacuous by construction** (a documented no-op — [lifted_grammar.py:86-92](../../../src/alphazeropp/synthesis/lifted_grammar.py#L86-L92)).

![Hole-kind state machine of the occurrence-introduced grammar](figures/02_derivation_state_machine.png)

> **Figure 2: Hole-kind state machine of the occurrence-introduced grammar.** *Read.* The four hole kinds plus the terminal, drawn as the finite-state machine a derivation runs over (`policy` → `action_schema` → `pre_lit` → `goal_lit`, back to `policy` on `FINISH_RULE`, to terminal on `STOP_POLICY`); each node annotated with its legal-production count $|A(s)|$. The `pre_lit` hole is the widest ($\le M$), because a state literal may put a fresh body-local variable in any argument position; $M=\mathrm{computeMaxProductions}(\mathrm{cfg},\sigma_A)$ sizes the MCTS action head. ### Production catalogue, what changed

| production | old grammar | new grammar |
|---|---|---|
| `ADD_RULE`, `STOP_POLICY` | as before | as before |
| `action_schema` (`schema=s`) | sets `schema` + schema-position action args; next hole `aux_var` | sets `schema` + schema-position action args (`?b_0`, `?r_1`, …, typed by $\sigma_A$); **next hole `pre_lit`** |
| `add_aux:T` / `SKIP_AUX` | introduce a standalone fresh `?aux_i:T`, or finish the aux phase | **removed** |
| `pre:ℓ` | each arg position is an existing in-scope var of the right type | each arg position is an existing in-scope var of the right type **or a freshly-introduced typed body-local var `?v_i`** (named by introduction order, left-to-right within the literal); capped by `max_body_local_vars` and `max_pre_literals`; literal sequence kept canonical by the strict lex key over `(source, predicate, args, negated)` |
| `STOP_PRE` | the analogous "close the precondition list" transition | always offered at the `pre_lit` hole — the only way out to `goal_lit` when `max_pre_literals` is not yet hit ([lifted_grammar.py:355](../../../src/alphazeropp/synthesis/lifted_grammar.py#L355)) |
| `goal:ℓ` | predicate in `goal_predicate_names` (when `goal_predicate_relevance`); arguments may include aux vars | predicate in `goal_predicate_names`; **all arguments must already be in scope** (action args ∪ body-local vars from positive state literals); a negated `Goal[ℓ]` only when every var in `ℓ` is positively covered (safe negation). **No fresh-var option.** |
| `FINISH_RULE` | builds `Rule(vars=action_args + aux_vars, …)` | builds `Rule(vars=action_args + body_local_vars, body=state_lits+goal_lits, action=LiftedAction(schema, action_args))` — already satisfies `Rule.__post_init__` ([Appendix B](#appendix-b-module-api-and-code-notes)) |

Because a goal literal introduces no variable, no grammar-produced rule can have a goal-literal variable that is unjustified by an action argument or a positive state literal:

$$
\boxed{\;\forall\,r\in\mathcal{R}_\Gamma:\quad \mathrm{ruleHasDisconnectedGoalVar}(r)\;=\;\mathrm{False}\;}
$$

— the predicate ([lifted_grammar.py:467-486](../../../src/alphazeropp/synthesis/lifted_grammar.py#L467-L486)) is kept only as a diagnostic over *arbitrary* policies; it is sampled against grammar-produced rules in `tests/test_lifted_grammar_occurrence_vars.py`.

The action head is a fixed width because the derivation game pads to the worst case. That width is

$$
M\;=\;\mathrm{computeMaxProductions}(\mathrm{cfg},\sigma_A)
$$

— [lifted_grammar.py:378-413](../../../src/alphazeropp/synthesis/lifted_grammar.py#L378-L413). For the strict Gripper-lite config $M=26$ (it over-approximates the new `pre_lit` candidate count — each arg position now has one more option per type; the old aux-var grammar's *default* config gave $M=13$, see [legacy/02.md](legacy/02.md)). `tests/test_lifted_grammar.py::test_compute_max_productions_is_a_real_upper_bound` asserts it stays a sound upper bound across `max_rules ∈ {1,3,4}` × `max_body_local_vars ∈ {0,1,2}` × the four `(goal_predicate_relevance, require_goal_var_connected)` flag combos.

### A worked derivation — hand-policy ρ₂ (the body-local-variable case)

Hand ρ₂ is `move(?from, ?to)` guarded by "robot at `?from`, holding ball `?b`, and `?b`'s goal room is `?to`". In the new grammar (action args named `?r_0`, `?r_1` by schema position; canonical literal order = state lits before goal lits, predicates lex-ascending):

| step | production | partial rule after |
|---|---|---|
| 0 | `ADD_RULE` | `schema=∅, args=∅, body_local_vars=∅, body=∅` |
| 1 | `action_schema: schema=move` | `schema=move, args=(?r_0:room, ?r_1:room), body_local_vars=∅` |
| 2 | `pre: at_robot(?r_0)` | `body=[at_robot(?r_0)]` — no fresh var (`?r_0` already in scope) |
| 3 | `pre: carrying(?v_0)` | `body=[at_robot(?r_0), carrying(?v_0)]`, **`body_local_vars=(?v_0:ball)`** — `?v_0` is the first fresh var, introduced here |
| 4 | `STOP_PRE` | precondition list closed; hole → `goal_lit` |
| 5 | `goal: at_ball(?v_0, ?r_1)` | `body=[at_robot(?r_0), carrying(?v_0), Goal[at_ball(?v_0, ?r_1)]]` — both args already in scope; introduces nothing |
| 6 | `FINISH_RULE` | `Rule(vars=(?r_0, ?r_1, ?v_0), body=(at_robot(?r_0), carrying(?v_0), Goal[at_ball(?v_0, ?r_1)]), action=move(?r_0, ?r_1))`; hole → `policy` |
| 7 | `STOP_POLICY` → `⊥` | (a 1-rule policy; the real hand policy has 4 rules — three more `ADD_RULE…FINISH_RULE` blocks before `STOP_POLICY`) |

7 productions for this rule — `ADD_RULE`, `schema`, two `pre:ℓ`, `STOP_PRE`, `goal:ℓ`, `FINISH_RULE` (vs 8 in the old grammar — the `SKIP_AUX` step is gone) — then `STOP_POLICY` for the policy. Up to α-renaming, the rule built at step 6 is hand ρ₂. `tests/test_lifted_grammar_occurrence_vars.py::test_all_four_hand_policy_rules_expressible` checks all four hand-policy rules are reachable by `canonical_rule_form` matching.

## §9 Best-policy examples and rollout traces

> **Goal.** Show, by rollout on a fresh env, that the headline solvers genuinely solve the task — they are not score-formula artifacts.

### Best B=1 solver — `b1_sims2048_seed4` (score 1.22, 3 rules, 3 literals)

```
ρ_1: at_ball(?b_0, ?r_1) ⇒ pick(?b_0, ?r_1)
ρ_2: carrying(?b_0) ∧ Goal[at_ball(?b_0, ?r_1)] ⇒ drop(?b_0, ?r_1)
ρ_3: ⊤ ⇒ move(?r_0, ?r_1)
```

A 3-rule decision list that picks any ball at the current room, else drops a carried ball at its goal room, else moves. Rollout on a fresh `GripperLiteEnv(1)` (`ball_0` in `room_a`, goal `at_ball(ball_0, room_b)`, horizon 8):

| t | rule fired | grounded action | resulting state change |
|---:|:---|:---|:---|
| 0 | ρ_1 | `pick(ball_0, room_a)` | `at_ball(ball_0,room_a)` → `carrying(ball_0)`, `¬handempty` |
| 1 | ρ_3 (ρ_1, ρ_2 don't fire) | `move(room_a, room_b)` | `at_robot(room_a)` → `at_robot(room_b)` |
| 2 | ρ_2 | `drop(ball_0, room_b)` | `carrying(ball_0)` → `at_ball(ball_0,room_b)`, `handempty` |
| 3 | — | — | `env.is_solved()` ⟹ **solved** (3 steps, 0 noops, progress 1.0 ⟹ score 1.22) |

ρ_2 has a body-local variable in *name* only here (`?b_0` is an action argument); other $B{=}1$ solvers in the grid genuinely use one — e.g. `b1_sims128_seed1`'s ρ_2 is `at_robot(?r_1) ∧ carrying(?b_0) ∧ carrying(?v_0) ⇒ drop(?b_0, ?r_1)` (a redundant second `carrying(?v_0)`), and `b1_sims128_seed4`'s ρ_2 is `at_robot(?r_0) ∧ carrying(?v_0) ∧ ¬Goal[at_ball(?v_0, ?r_0)] ⇒ move(?r_0, ?r_1)` — `?v_0:ball` is a fresh body-local introduced by `carrying`, exactly the mechanism §4's worked example shows.

### Best B=2 solver — `b2_sims2048_seed4` (score 1.18, 3 rules, 5 literals)

```
ρ_1: carrying(?v_0) ∧ Goal[at_ball(?v_0, ?r_1)] ⇒ drop(?b_0, ?r_1)
ρ_2: at_robot(?v_0) ∧ handempty() ∧ ¬Goal[at_ball(?b_0, ?v_0)] ⇒ pick(?b_0, ?r_1)
ρ_3: ⊤ ⇒ move(?r_0, ?r_1)
```

Here `?v_0` is a body-local *ball* in ρ_1 and a body-local *room* in ρ_2 (independent scopes). Rollout on `GripperLiteEnv(2)` (`ball_0`, `ball_1` in `room_a`, goal both in `room_b`, horizon 12):

| t | rule fired | grounded action |
|---:|:---|:---|
| 0 | ρ_2 | `pick(ball_0, room_a)` |
| 1 | ρ_3 | `move(room_a, room_b)` |
| 2 | ρ_1 | `drop(ball_0, room_b)` |
| 3 | ρ_3 | `move(room_b, room_a)` |
| 4 | ρ_2 | `pick(ball_1, room_a)` |
| 5 | ρ_3 | `move(room_a, room_b)` |
| 6 | ρ_1 | `drop(ball_1, room_b)` |
| 7 | — | **solved** (7 steps, 0 noops, progress 1.0 ⟹ score 1.18) |

It carries balls one at a time, returning empty-handed each round; the guards line up so the interpreter's lex-min unification picks a consistent ball at each `pick`/`drop`. The 4-rule `b2_sims512_seed1` solver achieves the same score with a wordier body (11 literals).

### The lone "reasonable non-solver" — `b2_sims2048_seed4`, unique idx ≠ 8 (score 0.045)

```
ρ_1: at_ball(?v_0, ?r_1) ∧ handempty() ∧ ¬Goal[at_ball(?v_0, ?r_0)] ⇒ move(?r_0, ?r_1)
ρ_2: at_robot(?v_0) ∧ Goal[at_ball(?b_0, ?v_0)] ⇒ drop(?b_0, ?r_1)
```

Fires `pick`, `move`, `drop` all legally and makes positive progress (≈ one ball delivered) but never finishes — hence `reasonable` rather than `solver` or `degenerate`. It shows the classification's middle bucket is non-empty.

## §10 Failure analysis

> **Goal.** Explain why $B=2$ is hard at this budget, and report it as the honest result it is.

A $B{=}2$ solver exists in the search space — we found one (§9) — but **the modal terminal policy under a uniform prior is degenerate (Comp):** 235 of 240 distinct $B{=}2$ terminals (and 553 of 560 $B{=}1$ terminals) are classified `degenerate`, meaning the first `interpret(...)` returns `None` or the rollout makes zero progress. Typical degenerate shapes in the raw logs:

- **Contradictory guards.** `ρ_1: at_robot(?v_0) ∧ carrying(?v_1) ∧ handempty() ∧ … ⇒ drop(…)` — `carrying(?v_1)` and `handempty()` can never both hold, so the only rule never fires; with a noop default the score floors at $-0.05$. The grammar has no semantic feasibility check on a rule body, so it produces these freely (see [Limitations](#13-limitations)).
- **Goal-typed dead ends.** A first rule headed `Goal[at_ball(?b_0, ?r_1)] ⇒ drop(…)` with no positive precondition: it *does* fire (any `at_ball` goal exists), but `drop` is illegal hand-empty, the interpreter returns `None`, and the rollout stalls at $t=0$.
- **Short policies dominate.** A uniform prior puts the most mass on the shortest derivations — `STOP_POLICY` is offered right after the first `FINISH_RULE` — so 1-rule policies are heavily over-sampled, and a single rule almost never solves Gripper for $B\ge1$ (the hand policy needs 3–4 rules covering `pick`, `move`, `drop`).

For $B{=}2$ the additional difficulty is combinatorial (Interp): a solving policy needs the `pick`/`move`/`drop` triad *and* the move-back step (the robot must return for the second ball), so it lives deeper in the derivation tree, where a uniform prior reaches it rarely. The 2 of 10 cells that solved did so by luck of the seed; the logs (`data/minimal_mcts/b2_*_summary.json`, `b2_*_best.jsonl`, and the raw `results/lifted_gripper_lite/minimal_mcts/b2_*/all.jsonl`) record which episode found the solver and what every other terminal looked like. **This is reported as the honest result it is** — a uniform-prior baseline that occasionally stumbles onto a $B{=}2$ solver — not as a success. Closing this gap is the job of a learned prior (later stages), which this stage does not build.

### Open questions

Whether the `sims=8192` tier (omitted under `--skip-slow`) raises the $B{=}2$ solver rate, and whether a learned prior turns "rarely" into "reliably" — both are deferred to later stages and unaddressed here.

## §13 Limitations

> **Goal.** State what is *not* proved by this stage.

- **Uniform-prior MCTS, not learned AlphaZero.** The prior is `UniformPolicyValueNet` (flat policy, zero value); every policy found is a *search artifact* — there is no learned policy or value here.
- **Same-$B$ only — no generalization.** Train, in-eval and out-eval all use one frozen `GripperLiteEnv(B)`. No $B=3$ result, no $J_{\text{out}}$, no claim that any found policy generalizes.
- **No Doors MCTS.** Doors has a relational adapter and a hand policy (Stage 1 rev. 1) but no synthesized policy.
- **No landscape, no score-variant plots, no PG3.** The Stage-2.5 program-space enumeration and the score-variant analyses are not run; there is no PG3 comparison.
- **`--skip-slow` was used for the committed $B{=}2$ grid** — the `sims=8192` tier is not in the data here (the full command is in §8).
- **Legacy `data/` artifacts.** `data/runA_*`, `data/runB_*`, `data/landscape_*`, `data/diagnostic_grid/` are aux-var-grammar outputs and are *not* regenerated; the legacy drivers carry a docstring note.
- **The grammar has no semantic feasibility check.** It produces rules with contradictory bodies (§10); only the leaf evaluator's rollout catches them, after the fact.

## §14 What is not claimed

Beyond the limitations in §13 (no learned net, no $B=3$/$J_{\text{out}}$, no Doors MCTS, no landscape/score-variant/PG3):

- Removing the `aux_var` *syntax* does **not** remove body-local variables — state literals still introduce them; the hand policy's ρ₂ and ρ₄ each need one.
- The $B{=}2$ result is honest, not spun: a uniform-prior baseline finds a $B{=}2$ solver in 2 of 10 grid cells; the modal terminal at this budget is degenerate.

> **Next.** A learned policy/value net over this same `LiftedDerivationGame`; held-out generalization ($B=3$, $J_{\text{out}}$); the `sims=8192` tier; Doors MCTS. None of these is run here.

## Appendix B: module API and code notes

Implementation-level renamings and gotchas pushed out of the body:

- **Hole / encoding renumber.** The `aux_var` hole is removed; `_HOLE_ID` ([lifted_encoding.py:34](../../../src/alphazeropp/synthesis/lifted_encoding.py#L34)) is `{None:0, policy:1, action_schema:2, pre_lit:3, goal_lit:4}`; the `_KIND_AUX_VAR` encoding node is deleted.
- **`PartialRule`.** `PartialRule.aux_vars` → `PartialRule.body_local_vars` ([lifted_derivation.py:50](../../../src/alphazeropp/synthesis/lifted_derivation.py#L50)), grown lazily as `pre:ℓ` literals introduce fresh vars.
- **`LiftedGrammarConfig`.** `max_aux_vars` → `max_body_local_vars` (default `2`; the hand policy needs `≤ 1`). `require_goal_var_connected` ([lifted_grammar.py:86-92](../../../src/alphazeropp/synthesis/lifted_grammar.py#L86-L92)) is kept for config-shape stability but vacuous by construction (documented no-op).
- **`FINISH_RULE`.** Builds `Rule(vars=action_args + body_local_vars, body=state_lits+goal_lits, action=LiftedAction(schema, action_args))`. The result already satisfies `Rule.__post_init__` (typed/declared vars, safe negation, no unused declared var, no goal-only var) with no new validation.
- **`compute_max_productions` rewrite.** Drops the aux-var term and over-approximates the new `pre_lit` candidate count (each arg position has one more option per type); for the strict Gripper-lite config $M=26$. A randomized test ([test_lifted_grammar.py::test_compute_max_productions_is_a_real_upper_bound](../../../tests/test_lifted_grammar.py)) checks soundness across the size/flag grid.
- **`git_commit` in the data.** The canonical grid was run from working-tree code on `feature/grammar-redesign` before this stage's commit landed, so each per-cell `summary.json` records `git_commit: "d9b867f"` (the immediately-preceding commit). The code that produced it is exactly the redesigned grammar + the run scripts described here.
