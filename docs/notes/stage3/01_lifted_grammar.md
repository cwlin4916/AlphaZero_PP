# Stage 3 / Design — Lifted Grammar: Typed CFG and Decision-List Semantics

## Overview

Stage 3's central move is **replacing object-indexed ground syntax** (Stage 1's $P_k, M_k$ tokens, Stage 2's $(2K)^{2K}$ unmasked words) with **typed lifted syntax** — bound variables of declared types — so the same symbolic policy schema applies across instance sizes. Stage 1's coverage bottleneck $C = \Theta(3^K)$ and Stage 2's super-exponential blowup are *coverage* problems, not search-power problems; lifting collapses both by sharing structure across objects of the same type. The result happens to be a typed CFG, but what matters is structural compression for cross-instance reuse, not raised expressive power.

Concretely, the Stage 3 policy class is a **bounded lifted decision list** generated by that typed CFG. Policies are sequences of rules; each rule is `if StateGuard ∧ GoalGuard then Act` with compositional predicate guards over typed variables. The grammar is finite and enumerable when four structural hyperparameters are capped.

## Anatomy of a lifted rule

Following PG3 (Yang et al. 2022, Definition 2), each rule $\rho$ has four components:
$$
 \rho:\;\; \underbrace{\textbf{if}\;\; \mathrm{PRE}(\rho)(\bar x) \;\wedge\; \mathrm{GOAL}(\rho)(\bar x)}_{\text{guard}} \;\; \textbf{then}\;\; \underbrace{\mathrm{ACT}(\rho)(\bar x)}_{\text{action}}
$$

| Component | Meaning | Example (Ferry "board a car") |
|---|---|---|
| $\mathrm{PAR}(\rho)$ | Typed parameters — variables of the rule | $\{c\!:\!\textit{car}, \ell\!:\!\textit{loc}, d\!:\!\textit{loc}\}$ |
| $\mathrm{PRE}(\rho)$ | State preconditions: conjunction of literals over the current state $S$ | $\texttt{at}(c,\ell) \wedge \neg\,\texttt{at}(c,d)$ |
| $\mathrm{GOAL}(\rho)$ | Goal preconditions: conjunction of literals over the goal $G$ | $\texttt{goal:at}(c,d)$ |
| $\mathrm{ACT}(\rho)$ | Action — must use only variables appearing in PRE or GOAL | $\texttt{board}(c,\ell)$ |

Execution: given $(S, O, G)$, find the first type-respecting binding $\theta : \mathrm{PAR}(\rho) \to O$ that satisfies every PRE and GOAL literal. Execute $\mathrm{ACT}(\rho)$ under $\theta$. (For the formal $\theta$ definition, the type-respecting condition $\theta(x_i) \in O_{\textit{type}(x_i)}$, and the ground-atom-vs-lifted-literal distinction, see [02_doors_adapter.md §"Notation"](02_doors_adapter.md).)

## The CFG — formal productions

$$
\begin{aligned}
 \text{Policy}_0 &\to \text{Default} \\
 \text{Policy}_{\ell+1} &\to \text{Rule}\,;\,\text{Policy}_\ell \;\mid\; \text{Default} && (0 \leq \ell < L_{\max}) \\
 \text{Rule} &\to \textbf{if}\; \text{StateGuard}\; \text{GoalGuard}\; \textbf{then}\; \text{Act} \\
 \text{StateGuard}_0 &\to \top, \quad \text{StateGuard}_{k+1} \to \text{Lit} \;\mid\; \text{Lit} \wedge \text{StateGuard}_k && (0 \leq k < K_s) \\
 \text{GoalGuard}_0 &\to \top, \quad \text{GoalGuard}_{k+1} \to \text{GoalLit} \;\mid\; \text{GoalLit} \wedge \text{GoalGuard}_k && (0 \leq k < K_g) \\
 \text{Lit} &\to p(\vec x) \;\mid\; \neg\,p(\vec x) && p \in \mathcal P \\
 \text{GoalLit} &\to \texttt{goal:}p(\vec x) \;\mid\; \neg\,\texttt{goal:}p(\vec x) && p \in \mathcal P \\
 \text{Act} &\to a(\vec x) && a \in \mathcal A
\end{aligned}
$$

$\vec x$ is drawn from a bounded typed variable pool of size $\leq V_{\max}$ per rule.

This is a **typed CFG**, not a right-linear grammar. The outer policy layer is a decision list; the inner guard language is tree-structured (compositional conjunctions).

Typed variables do *not* raise the grammar above context-free — the CFG generates abstract syntax and a separate type system rejects ill-formed trees. The right framing is *typed DSL grammar* (cf. SyGuS / syntax-guided synthesis; see [appendix/sygus_background.md](../appendix/sygus_background.md)), not context-sensitive grammar.

## Structural hyperparameters

| Parameter | Meaning | Typical initial value |
|---|---|---:|
| $L_{\max}$ | Maximum number of rules in the decision list | 3–5 |
| $K_s$ | Maximum state literals per rule guard | 2–3 |
| $K_g$ | Maximum goal literals per rule guard | 1–2 |
| $V_{\max}$ | Maximum typed variables per rule | 3–4 |

Total grammar size is a function of these bounds and the adapter's $\lvert\mathcal P\rvert$, $\lvert\mathcal A\rvert$, $\lvert\mathcal T\rvert$. **Design principle:** start with small bounds for exact enumeration (tiny-enumeration experiment), increase for training-based search.

These bounds play the same role as $L_{\max} = 2K$ in Stage 2 — they cap derivation depth and control the combinatorial search space.

## Unpacking the state guard

The subscript on $\text{StateGuard}_k$ is a **recursion depth counter**, not a vector index. It limits how many literals can be conjoined.

| Production | Expands to | Meaning |
|---|---|---|
| $\text{StateGuard}_0 \to \top$ | (empty) | "always true" — no conditions |
| $\text{StateGuard}_1 \to \text{Lit}$ | $\texttt{at}(c,\ell)$ | One literal |
| $\text{StateGuard}_2 \to \text{Lit} \wedge \text{StateGuard}_1$ | $\texttt{at}(c,\ell) \wedge \texttt{on}(c)$ | Two literals ANDed |
| $\text{StateGuard}_3 \to \text{Lit} \wedge \text{StateGuard}_2$ | $\texttt{at}(c,\ell) \wedge \texttt{on}(c) \wedge \texttt{empty\_ferry}()$ | Three literals |

$K_s$ caps the maximum depth and therefore the maximum number of literals per guard. $K_g$ does the same for goal guards. Each $\text{Lit}$ chooses a predicate $p \in \mathcal P$, a polarity ($+$ or $\neg$), and fills argument slots from the rule's variable pool.

## Decision-list semantics

Given an observation $(S, O, G)$:

1. **First-applicable rule.** Scan $\rho_1, \rho_2, \ldots, \rho_n$ top to bottom. Fire the first rule whose guard is satisfiable.
2. **Type-respecting binding.** A rule with variables $x_1, \ldots, x_m$ is applicable if there exists $\theta : \{x_i\} \to O$ respecting types such that every state literal holds in $S$ and every goal literal holds in $G$.
3. **Deterministic tie-breaking.** If multiple bindings satisfy the guard, choose the lexicographically first object tuple. This ensures identical behavior across implementations.
4. **Default fallback.** If no rule applies, execute the `Default` action (a domain-defined no-op or failsafe).

No stochasticity at execution time. Grammar search is the only source of combinatorics. This mirrors PG3's lifted decision-list semantics exactly.

### Worked example — Doors $D = 3$

To make the binding mechanics concrete, walk through one episode of Doors at $D = 3$ ($K = 2$). Object sets: $O_{\textit{room}} = \{r_0, r_1, r_2\}$, $O_{\textit{key}} = \{k_0, k_1\}$. Static facts: $\textit{key\_for}(k_0, r_1)$, $\textit{key\_for}(k_1, r_2)$. Goal: $G = \{\textit{at\_agent}(r_2)\}$.

A minimal three-rule reactive lifted policy:

| Rule | Guard | Action |
|---|---|---|
| $\rho_1$ | $\textit{key\_available}(k) \wedge \textit{key\_for}(k, r) \wedge \textit{locked}(r)$ | $\textit{pick}(k)$ |
| $\rho_2$ | $\textit{has\_key}(k) \wedge \textit{key\_for}(k, r) \wedge \textit{locked}(r)$ | $\textit{move\_to}(r)$ |
| $\rho_3$ | $\textit{at\_agent}(g) \wedge \textit{goal\_room}(g)$ | $\textit{finish}$ |

**Execution trace.**

- $S_0 = \{\textit{at\_agent}(r_0),\, \textit{key\_available}(k_0),\, \textit{locked}(r_1),\, \textit{locked}(r_2)\}$.
  Scan: $\rho_1$ is applicable with binding $\theta_0(k) = k_0,\, \theta_0(r) = r_1$ (satisfies all three literals); fire $\textit{pick}(k_0)$.
- $S_1 = \{\textit{at\_agent}(r_0),\, \textit{has\_key}(k_0),\, \textit{locked}(r_1),\, \textit{locked}(r_2)\}$.
  Scan: $\rho_1$ no longer applicable for $k_0$ (no $\textit{key\_available}$); $\rho_2$ fires with $\theta_1(k) = k_0,\, \theta_1(r) = r_1$; emit $\textit{move\_to}(r_1)$.
- The cycle repeats for $k_1, r_2$, then $\rho_3$ fires under $\theta(g) = r_2$ and emits $\textit{finish}$.

The policy is **constant-size** (three rules) and **object-index-free**: the same three rules execute on $D = 4, 7, 100$ provided the predicate vocabulary is rich enough. Whether this constant-size form actually transfers across $D$ on Doors is what Exp 2 tests; if a flat list cannot find the right binding-discipline at large $K$, the candidate `ForEach` extension below is the planned fallback.

## Why decision-list semantics

1. **Priority ordering.** Earlier rules take precedence; urgent cases are handled before general fallbacks.
2. **Determinism.** Exactly one action per state — no ambiguity.
3. **Compositionality.** Adding a rule to the front handles a new case without breaking existing behavior; later rules are simply shadowed.

Because the CFG generates *sequences* of rules and order matters, the grammar production $\text{Policy}_{\ell+1} \to \text{Rule}\,;\,\text{Policy}_\ell$ *prepends* a rule to the list at each derivation step. Permuting the same three rules yields different policies — policy synthesis becomes a sequence-ordering problem, a natural fit for grammar-guided MCTS.

## Design subtleties

| Issue | Resolution |
|---|---|
| **0-arity predicates** | $\texttt{empty\_ferry}()$ has no variables. Grammar must allow $p()$ with empty arg list; literal is trivially checkable. |
| **Action vars ⊆ guard vars** | Every variable in $\text{Act}$ must appear in $\text{StateGuard}$ or $\text{GoalGuard}$ — otherwise the binding is undefined. PG3 enforces this; so do we. |
| **Static predicates** | Relations like $\texttt{key\_unlocks}(k, r)$ in Doors are fixed per instance. Not in $S$, but available to guards as compile-time constants from the adapter. |
| **Default must be 0-ary** | The default action has no guard and therefore no binding context. Must take zero arguments (e.g. $\texttt{noop}()$). |
| **Type constraints ≠ masks** | Typing restricts which variables fill which argument slots. Structural constraint from the vocabulary, not a domain-specific semantic mask. |

These constraints are **domain-independent** — they follow from the grammar schema itself, not from any game's semantics.

## Reactive form vs program-compiler form

Two distinct policy targets sit behind any lifted-syntax design; the choice determines whether `ForEach` reads as essential or as one option among several.

| Target | Signature | Execution | Closest analogue |
|---|---|---|---|
| **Reactive** | $\pi(S, G) \to a$ | Re-applied at every state; first applicable rule fires under a fresh binding $\theta$ each step | PG3 |
| **Program-compiler** | $\Pi(O, I, G) \to [\textit{macro sequence}]$ | Compile once per instance; emit a macro sequence that is then executed open-loop | Stage 1 / Stage 2 surface programs |

Stage 3 commits to the **reactive** form. Decision-list semantics (next section) are written for $\pi(S, G) \to a$, and the bootstrap reasoning of Stages 1–2 (rollout reward, MCTS over derivations) is preserved. The program-compiler form is the natural successor to Stage 1/2's `UnmaskedSurfaceDerivationGame` — it generates a whole macro sequence in one shot, and `ForEach(\tau, \textit{rules})` is most natural in this regime (e.g. $\textit{ForEach}(r\!:\!\textit{room}, \textit{locked\_path\_order})$ expanding on the $D=3$ Doors instance to $P_0, M_0, P_1, M_1, G$). Stage 3 keeps program-compiler form on the table but does not commit to it; the next section's `ForEach` discussion is therefore framed as a candidate fallback within the reactive grammar, not a regime change.

## Candidate extension: `ForEach` for Doors

Doors has a single goal literal ($\texttt{at\_agent}(\textit{goal\_loc})$) rather than per-object goals. A flat lifted decision list *might* need $\sim 2K$ rules for Doors (one pick + one move per key), in which case $L_{\max}$ would have to scale linearly with $D$ — which would defeat the "policy transfers across sizes" premise. Whether the flat form actually fails is open: a sufficiently rich state-guard vocabulary may still let one or two reactive rules solve all $D$.

Candidate resolution: Stage 3 reserves a generalized iteration construct $\texttt{ForEach}(\tau, \textit{rules})$ as a *fallback* grammar element for single-goal-literal domains. Whether to enable it on Doors is decided by Exp 2: if a flat reactive decision list transfers across $D$, `ForEach` is unnecessary; if not, it is the planned extension beyond PG3's flat decision lists.

**Stage 3 grammar = flat PG3 lifted decision list, optionally extended with $\texttt{ForEach}(\tau, \textit{rules})$ if Exp 2 shows the flat form does not transfer on single-goal-literal domains.**
